Settings — structure & navigation

Settings becomes a full page with a list of pages, search and direct links, instead of one long modal. This board shows the options considered, the new page, where each current setting goes, and how search and navigation work. The pages themselves and their states are on the next board.
A. What is wrong today and the options
Settings opens as a modal with 11 sections in one scroll. They mix settings for one project (Git repositories, Docs, AI) with settings for the whole app (Theme, Data folder, Updates, Logs), and more keep being added. Finding one means scrolling and reading headings.

B. The new Settings page
Opens in the main area like Docs, replacing the board view. A list of pages on the left, grouped as Project settings (for the project chosen at the top) and App settings (for this app, all projects). Search sits at the top. Each page is short and has its own link. Back to board returns to where you were.

E. How it behaves
Proposed.
Opening and leaving
  • The sidebar Settings button opens the page; Back to board or Esc returns to the view you came from.
  • Every page and every setting has its own link, so other screens can send you straight there (for example “Manage budgets” from AI members).
  • Opens on the page you used last. The first time, it opens on the first page with something that needs attention, otherwise on Repositories.
  • Needs-attention badges on the list: invalid AI key, update ready, runner not found.
Project and app settings
  • The picker at the top of Project settings chooses which project you are editing. Pages say which project in their title.
  • App settings look the same whichever project is open.
  • Items that exist only in the desktop app (Updates, installing MCP) are hidden on the web, not greyed out.
  • People without permission see settings read only, with a line saying why.
Saving and leaving
  • Same as today: each section saves itself and shows a short “Saved” or the error beside its title. No page-wide Save button.
  • A section with edits not yet applied (for example a path typed but not applied) warns when you leave the page.
  • Dangerous actions (Import, which replaces all data) ask inline in the section instead of a browser pop-up.
  • Narrow windows: the list collapses into a drop-down at the top of the page.
