Board AI that acts, knowledge base, pull request status

The Board AI does what it can undo and says what it did; what it cannot undo it asks you as a normal question. Next to it: a knowledge base that the teams search, the status of the pull request a team opened for a ticket, and two notification events. Desktop only. Sample project: Kanban Board (KAN).
A. What it does, and what it asks about
One question decides it: can the board put this back by itself? A person’s answer to a question it asked is the go-ahead.
Does it, and says so
What can be undone is done at once, then listed in a receipt with Undo all.
  • Move a ticket, assign it, set labels or priority
  • Add a comment
  • Add a sub-task or a checklist item
  • Create a ticket
  • Edit one section of a Docs page
  • Give a ticket to an AI team
Recorded as the person who asked, “through the Board AI”.
Asks you a question
What cannot be put back is put to you as a question in the chat, with the answer box a team uses.
  • Delete a ticket, a page or anything else
  • Remove a member
  • Pause all AI
  • Merge
It never force-pushes and never leaves the project folder.

How an AI actually finds something
Table of contents
One line per document. It reads this first, and often that is enough to know which file it wants.
Keyword search
BM25 over the text, the summaries and the keywords. It tries more than one wording, the way it does with code.
Read
It opens the part it needs, not the whole file.
Three MCP tools: knowledge_index, knowledge_search, knowledge_read. Results say which store they came from.
Who sees it, and what it is allowed to say
  • A document is only as visible as its source. A Docs page that is private stays private: it is indexed for the people and teams that could already open it, and never becomes reachable through the shared store.
  • The shared store is for things meant to be shared — company conventions, a security review. Adding a project document to it is a deliberate move and says who will be able to read it.
  • An uploaded file is untrusted input. Its text is fenced and labelled with its source before any AI reads it, the same way a guest comment is, so a line inside a PDF cannot act as an instruction.
  • Permissions are still enforced outside the model: a document cannot widen what an AI is allowed to do, whatever it says.
Why not embeddings
  • You did not want documents going to an embedding service, and a local model is slow enough to be felt on every lookup.
  • Claude reads these documents anyway when it works, so sending them to one more service buys nothing and adds a key.
  • For a store this size, a table of contents plus BM25 is what a person would do, and it is explainable when it goes wrong.
  • It stays an option. If a store grows past what keyword search can handle, embeddings become a switch — not a rewrite.

G. The states these screens have to have
Most of these exist because the Board AI now does things. A thing that was done needs a way of being seen, refused, taken back and explained.
Undo is too late
Something else changed the same field. The button says what overwrote it and when, and offers to open that change rather than failing silently.
It did half of it
Three of five changes went through and the fourth was refused. It says which, why, and offers to undo the three.
Your role will not allow it
A Viewer’s Board AI says “I can look this up but I cannot change it — your role is Viewer”, and does not do it either.
The knowledge base is empty
A new project. “Nothing here yet. Add a file and the teams can look things up in it.” Not an error.
A file could not be read
A scanned PDF with no text layer. It says so on the row and offers to run it through a model once, rather than silently indexing nothing.
GitHub is unreachable
The polling says last checked 20 minutes ago instead of pretending CI is green.
The Board AI is off
Turning the feature off hides the chat and the cards, and nothing is left half-running.
