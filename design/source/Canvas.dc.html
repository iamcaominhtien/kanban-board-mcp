Screen — v1 proposal

Canvas — boards, notes and comments on one large plane

A Canvas is a third drawing object next to Sketch and Diagram: design boards (HTML pages, images, Sketches, Diagrams) side by side on one large plane, with notes and arrows. It appears wherever they appear, and can also live as its own Docs page. This board shows where you start one, the editor, how people and AI change boards and comment, how it looks in ticket descriptions, comments, ideas and Docs, how to view and present it full screen, versions, files in and out, and what happens when something goes wrong.
A. What Canvas is, in one table
The decisions the rest of this board follows. Open points are in section M.
QuestionDecisionWhy
What it is
A Canvas is a third drawing object, next to Sketch and Diagram. Design boards (HTML pages, images, Sketches, Diagrams) sit side by side on one large plane, with notes and arrows between them.
Teams review screens as separate files. Laid out together they can be compared, discussed and walked through in order.
Where it appears
Everywhere Sketch and Diagram appear: ticket descriptions, comments, Docs pages and ideas, the markdown toolbar, the slash menu, the New idea dialog, and “open this file/picture in…” in Preview. Same buttons, same place.
One mental model for all three. Nobody has to learn where Canvas lives.
Who owns it
Either the place it was inserted in (a ticket, comment, page or idea), as an attachment like a drawing, or its own Docs page of type Canvas, in the page tree. It is the same canvas either way: Move to Docs turns an inline canvas into a page, and the text it came from keeps showing it.
Small canvases stay next to their work. Ones that many tickets share get a stable home, with page history, access and backlinks.
How it looks in text
A live card: an overview of the boards, a footer with name, number of boards and who edited it, and the same hover actions as a diagram (Edit, Download, View full size, Copy link). One board can be embedded alone.
Always the latest version. Narrower in tickets and comments, wide in Docs.
What is on the plane
Boards, notes, arrows and labels. Boards are grouped into named pages (tabs) so a long canvas stays readable.
Enough to explain a flow. Not a whiteboard: free drawing is Sketch, shapes and connectors are Diagram.
Who changes it
People, and AI members that are allowed to. Moving, notes, arrows and comments are free for everyone. Changing what is inside a board locks that one board for the person doing it.
Same rule as Docs and Sketch: no editing together in v1, so there is never a merge.
What AI does
Reads the canvas, comments on boards, and proposes a changed board. The person sees before and after and accepts or rejects.
Follows the proposal pattern already used in Docs AI.
How a board is shown
In a locked frame (no scripts, no outside requests), as HTML is in Preview. Any width from 320 to 1920.
Safe by default; the same picture for everyone.
Where it works
Desktop and web. On a phone the canvas opens read only, one board at a time.
Like Sketch and Diagram.

  • Drag a board by its name or its body. Guides and snapping appear next to other boards.

  • New boards are placed to the right of the last one, never on top of another.

H4. Full screen and focus
How the three ways to look differ
  • Large view (click an embed): look, step through, comment. No editing tools.
  • Editor (Edit, or Open canvas): the whole plane, with tools.
  • Present (header button, or P in either): a screen for a meeting. Starts at the selected board.
  • F in the editor hides the header, tabs and panel for more room, without leaving the editor.

M. Where the data comes from, and what to confirm
A canvas is a small file that points at boards stored the way attachments already are. Most of the work is the plane (move, zoom, select), the locked frame (it exists in Preview) and the proposal flow (it exists in Docs AI).

To confirm before building
  • The word “board”. The app already has a Board view (Board, List, Timeline). Boards on a canvas could be confused with it. Recommended: call them frames everywhere in the UI. This design uses “board” so the proposal reads like the canvas the team already knows; changing the word is text only.
  • Both an object and a Docs page. This design lets a canvas be inline (an attachment of its owner) or a Docs page, and moves one into the other with Move to Docs. Confirm the second form is wanted in v1, or ship inline first.
  • Page history of a page that embeds a canvas. Showing the canvas as it was at that page version needs a frozen copy per page version. Cheaper: always show the latest and say so in the history.
  • Limits. 60 boards, 5 MB per board, 50 MB per canvas, 10 page tabs are proposals. Sketch is 10 MB and Diagram 2 MB.
  • HTML boards. One file, or a folder with its CSS, images and fonts? This design assumes a folder, with the same locked frame as Preview (no scripts, no outside requests). A ZIP of a built page then works.
  • Lock time. 10 minutes idle, shown to the person first. A different value is only a number.
  • Sketch and Diagram boards are live. A board that holds one shows its latest version, so editing the Sketch elsewhere changes the board.
  • AI. AI members need the same permission as for editing Docs, and read the canvas as boards, notes and comments. Cost shown as for other AI work. They never take a lock from a person.
  • Realtime. No live cursors or editing together in v1. Layout changes (moves, notes, arrows) merge by item, so two people can arrange at once; only the same item changing twice conflicts.
  • Present and the large view are read only and take no lock. Whether Present needs a person to hold the keys (shared screen, remote control) is not designed.
  • Export of a Docs page that holds a canvas writes its overview PNG, as sketches and diagrams do.
