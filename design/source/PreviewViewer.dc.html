Desktop app only. Open in app, Show in folder and Download sit together in the header; the same actions appear on the card for files with no preview.

F. Rules
Proposed. Replaces the current separate previews with one component.
One viewer for everything
  • Replaces FilePreviewModal, the workspace PreviewPanel and the image modal built into the markdown renderer.
  • Anything that shows a file or image only says “open this”. The viewer decides how to show it.
  • The viewer is given the set of files in the current place (description, comment, page, attachments), so next / previous always makes sense.
  • Desktop app: Open in app and Show in folder. Web: Download and open. Files that can run ask first.
Safety and size
  • SVG is shown as an image, never as page code. HTML files are shown as text only.
  • Office files and archives are read without running anything. Macros, scripts and links inside are ignored.
  • Archive listing has caps on entries and unpacked size, so a zip bomb cannot hang the page.
  • Large files show a limited preview with a clear note and a Download button.
Quality
  • Opens with a loading state at once; heavy readers (PDF, Office) load only when needed.
  • Focus stays inside the viewer, returns to the thumbnail that opened it, and Esc always closes.
  • Images keep their alt text; every control has a label for screen readers.
  • Phones: the same viewer full screen with swipe and pinch (not drawn here).
