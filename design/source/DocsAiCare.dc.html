Docs AI — keeping docs true, team edits, comments and control

The second half of Docs AI: spotting pages that no longer match the board, seeing what a team changed on a page and undoing it, turning pages into tickets, sending comments to a team, and the few settings left. A team of Claude Code edits a page directly; the page’s history is the way back.
A. Keeping pages true
Docs go stale quietly: the ticket is Done and the page still says “not enforced yet”. AI is good at this comparison, so it does the checking. A banner appears on the page for editors and the list of everything is in Docs health; fixing the page is up to a person, or to a team they send the comments to (F).

How it decides
  • It compares a page with the tickets it links to (status, title, recent comments) and with the pages it links to. It does not guess from the page alone.
  • Every reason names what it compared, so you can check it in a few seconds.
  • It runs daily and when you ask. A page is only flagged again when something it depends on changes after you chose “Still correct”.
What it never does
  • It never edits a page itself. Fixing is a person’s job, or a team’s once you send it the comments (F).
  • It never flags a page for being old. A page nobody needs to change is not out of date.
  • It never marks a page as wrong in front of readers. The banner shows to people who can edit the page.
Digest and noise
  • The Monday digest uses the same Board health digest as tickets, one line per page.
  • Dismiss has three levels: this time, 30 days, or never for this kind of reason. Ignored items are remembered per page.

Rules
  • Items that already have a ticket chip or are ticked are skipped, and the dialog says so.
  • People named in the text are suggested as assignee, never set. The default is Unassigned.
  • Tickets are created in the project and column you choose (Backlog by default), with a link to the page. Nothing is created until you press the button.
  • A page with no action items says so: “No unchecked items without a ticket.”

J. Rules
How Docs AI behaves, in short.
A team edits directly, and you can go back
  • A team of the project can edit a published page. The page says who, when and which version, with See changes and Undo (B).
  • Undo goes back one version and keeps it as a new one; nothing is erased from History.
  • A page written with AI is a private draft. Publish warns while Needs input markers remain.
  • Published text is not stamped as AI. History marks versions where the author accepted AI text.
Honest and private
  • Answers cite the sections they used, or say the docs do not cover it. When pages disagree, it shows both.
  • AI reads only pages the asker can see.
  • “What will be sent” is shown before any request that writes. Page text is treated as data, never as instructions.
  • Ticket keys and page links in AI text are checked to exist before they are shown.
Cost and records
  • Cost and tokens are shown when the run reports them; otherwise “Not metered”.
  • Docs AI answers as the team chosen in Settings, with that team’s account, limits and budget.
  • Everything here works from the keyboard: Tab switches Search and Ask, Tab accepts, Esc discards.
