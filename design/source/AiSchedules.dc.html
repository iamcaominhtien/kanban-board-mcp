AI — schedules

Let an AI member work on a ticket at a set time, once or on repeat. Each schedule says when, which AI, when it counts as done and who reviews it. It starts the same kind of AI run as today. A new Schedules tab shows everything in one place, and each ticket can still set up its own. Desktop only. V1 is one ticket per schedule.

The Schedules tab joins Board, List, Timeline and Docs. From a ticket, the Run button and the assign popover both offer Schedule.

G. Rules
Proposed. Defaults are chosen to fail safe: when unsure, skip and tell a person.
Running a schedule
  • At the time, the board checks permission, budget, slot and runner. If all pass, it starts a normal AI run, tagged scheduled.
  • The AI reads the ticket as it is then, not as it was when scheduled. Ticket text is untrusted, as for any run.
  • A schedule can never raise permissions. The status ceiling stays Review.
  • A repeating schedule does not start a new run while its last run is still going.
  • Starts are guarded so a restart never runs the same slot twice.
Done and review
  • Machine checks decide: criteria ticked, test command exit code, summary posted, PR linked.
  • AI checks are judged by the reviewer and shown as such, never as hard facts.
  • Partly done keeps the ticket where it is and tells the assigner which checks are missing.
  • The reviewer must be a different AI. Review cost counts toward the daily budget.
  • Three failed runs in a row pause the schedule.
Offline and ownership
  • Local runners work only while the desktop app is open. Default: catch up for 2 hours, then skip and tell the owner.
  • API-key AIs run on the board, so they do not depend on a desktop.
  • The creator owns the schedule. Admins can pause or delete any schedule.
  • If the creator loses permission, the schedule pauses instead of running.
  • Schedules appear on the ticket, the board card, the Schedules tab and Activity.
