AI — schedules

A schedule starts a run of an AI team on a ticket at a set time, once or on repeat. It only starts the run: the team’s lead decides what to do and reports. Each schedule says when, which team and what to do if it cannot run on time. A Schedules tab shows everything in one place, and each ticket can set up its own. Desktop only. One ticket per schedule.

G
Rules
Defaults are chosen to fail safe: when unsure, skip and tell a person.
Running a schedule
  • At the time, the board checks that the team can start (not paused, signed in, within budget, a free run). If so, it starts a normal run, tagged Scheduled.
  • The lead reads the ticket as it is then, not as it was when scheduled. It decides what to do and writes the report.
  • A repeating schedule does not start a new run while its last run is still going.
  • Starts are guarded so a restart never runs the same slot twice.
How a start ends
  • Finished: the lead reported. Partly done: the run stopped at its limit; the lead’s report says what is left.
  • Failed: the run failed after its retries.
  • Three failures in a row pause the schedule and tell the owner.
  • A schedule never moves a ticket: the team and people do that.
Closed app and ownership
  • Teams run while the desktop app is open. Default: catch up for 2 hours, then skip and tell the owner.
  • The creator owns the schedule. Admins can pause or delete any schedule.
  • If the creator loses permission, the schedule pauses instead of running.
  • Schedules appear on the ticket, the board card, the Schedules tab and Activity.
