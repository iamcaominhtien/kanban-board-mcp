Guideline — design of the user and administrator guide

The look and structure of one guide for the whole product, in English, for people who use the app and for people who install and connect it. It shows the chapter plan, every kind of page (cover, contents, chapter opener, steps, reference, troubleshooting, quick start, shortcut sheet, privacy, administration), the parts they are built from, and the rules. It is a design: the chapters are not written yet.
A. What the guide is, and its shape
One guide, in English, for people who use the app and for people who install and connect it. About 166 pages (A4), in seven parts. Each chapter carries tags (Everyone, Admin, Developer, Desktop app, AI) so readers can skip what is not for them. The same source also produces a web version, and six short companions: a one-page quick start, a one-page shortcut sheet, and guides for administrators, MCP, privacy and troubleshooting, which are chapters here and also stand-alone PDFs. Page counts are a budget, not a promise.

4 · TicketsKanban Board User Guide
4.2 Create a ticket

A ticket is one piece of work. Create it when you want to track something, even if you are the only person who will ever see it.

1
Open the project and press New Ticket, or press CtrlN.
2
Type a title. Everything else can wait.
Choose a type (Task, Bug, Feature or Chore) and a priority if you know them.
3
Press Create Ticket. The ticket appears in Backlog.
Tip
Start with only a title. Add a description, tags and dates once the work is real.
Warning
A ticket needs at least a title. Everything else is optional until you move it to Done, if your project uses “Done requires” guards.
4.3 Move a ticket

Drag the card to another column, or open the ticket and use the status menu. The status menu also offers Won’t Do.

AI
Assign the ticket to an AI member to have it started for you. It stops at Review.

23.2 The 11 tools

Agents see these tools over MCP. Write tools take an action; the tool description lists every action and its parameters.

get_projectsreadAll projects, or one with its members
list_ticketsreadCompact, paginated ticket summaries
get_ticketreadOne ticket with recent activity, or just its comments
docs_readreadDocs tree, pages, search, versions, diagrams
manage_projectwriteCreate and update projects, members
manage_ticketwriteCreate, update, move, link, block, workspace
ticket_itemswriteComments, work log, criteria, sub-tasks, test cases
ticket_brancheswriteGit branches for a ticket
docs_writewriteCreate, update, move, import pages and diagrams
ai_runwriteInside an AI run only: ask, report
ai_schedulesdestructiveList, create, pause, run AI schedules
Note
The MCP address is http://localhost:8000/mcp/. The trailing slash is required.
23.3 Connect Claude Code

Use Settings › MCP integrations, or run this once:

claude mcp add kanban --scope user -- <path to kanban-mcp-stdio>
Tip
Idea Space tools are hidden by default. Set KANBAN_MCP_IDEA_TOOLS=1 to expose them.

25 · TroubleshootingKanban Board User Guide
25.1 Common problems

Find the symptom, then follow the fix. If nothing here helps, send a report.

SymptomCauseFix
The app shows “Connecting…” and never opensThe local server did not startPress Retry. If it repeats, Help › Show Logs in Finder and send the newest file.
An agent cannot connect to MCPThe address has no trailing slashUse http://localhost:8000/mcp/.
An AI member never startsThe runner is not installed or not signed inOpen Members, choose the AI, press Test connection.
A diagram has no pictureNo browser to draw it inInstall Chrome, Chromium or Edge, or set KANBAN_CHROME_PATH.
Check for Updates failsGitHub is limiting requestsWait a while, or open the releases page and download by hand.
25.2 Still stuck? Send a report
1
Choose Help › Export Logs… and save the file.
2
Choose Help › Report an Issue…. The window shows what will be filled in. Nothing is sent by the app.
3
In GitHub, attach the log file and describe what you did.
Note
Reports never include your tickets, Docs, file paths or keys unless you write them yourself.

24 · Privacy and dataKanban Board User Guide
24.1 Where your data goes

Kanban Board is local-first. Your projects live on your computer. Nothing leaves it unless you use a feature that talks to an AI provider.

Your computer
•Database (tickets, Docs, ideas)
•Attachments and workspace folders
•Logs
•Settings and API keys
only when you use AI
AI provider
•Anthropic, OpenAI, Google or your own endpoint
•Or the signed-in CLI on your computer (for example Claude Code)
24.2 What an AI feature receives
Sent for the question you ask
•The text you ask about: a ticket, a page or a selection
•The comments and linked pages needed to answer
•The instructions you wrote for that AI member
Not sent
•Projects, tickets and Docs you did not open or cannot see
•Your API keys
•Your data folder or backup
To confirm before publishing
The lists above follow the design. Check each line against the code (what exactly is put in a prompt) before this page is released.
24.3 Turn it off

AI help can be turned off for a project or for the whole board. With it off, the app makes no request to any AI provider.

21 · Data, backup and restoreKanban Board User Guide
21.2 Back up your data

Everything you care about is in the data folder. A backup is one file you can keep anywhere.

data folder
  ├ database file
  ├ attachments/
  └ logs/
1
Open Settings › Storage & backup.
2
Press Export data and choose where to save the ZIP file.
It contains the database and the attachments. Workspace folders are not included.
3
To restore, press Import data… and choose the ZIP.
Import replaces everything. You are asked to confirm first.
Caution
Importing a backup replaces all current data. Export a fresh copy first if you are not sure.

D. Rules for writing and building
Proposed.
Writing
  • Plain English. Short sentences. Name things as the app does (“Settings”, “Idea Space”, “Export Logs”).
  • Headings say what you can do (“Create a ticket”), not what the feature is called.
  • One screenshot per step at most, with numbered markers. No screenshot of a screen that only has text.
  • Each chapter starts with what it is for and what you need, and ends with where to go next and what to do if it fails.
  • Do not state a fact that comes from code without a check (limits, defaults). A page marked “to confirm” is not released.
Making the PDF
  • A4 portrait. 20 mm margins. Body 10 pt on 15 pt lines. Tagged PDF with bookmarks and alt text; fonts embedded.
  • Prints well in black and white and on Letter paper (the page area is the same).
  • Screenshots are taken by a script from a demo project, at 1440 × 900, so they can be redone when the UI changes. JPEG, about 1500 px wide.
  • The version on the cover, footer and back cover is read from the code. A build fails if a figure is missing.
  • Chapters for features that are not released are left out of the printed guide and kept in the source as drafts.
One source, several outputs
  • Each chapter is one source file with a list of audience tags.
  • Outputs: the full PDF, the web version, and the stand-alone PDFs (quick start, shortcut sheet, administration, MCP, privacy, troubleshooting).
  • The shortcut sheet and the Keyboard Shortcuts window read one list.
  • The PDF is attached to every release. The “Documentation” item in the Help menu opens the web version.
