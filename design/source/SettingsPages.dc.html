I. Where does a new setting go?
So the page does not grow into one long list again.
Choosing the page
  • If it changes one project only, it goes under Project settings; if it is the same everywhere, under App settings.
  • Pick the page by what the person is trying to do (“back up my data”), not by which part of the code it belongs to.
  • A feature gets a page only if it has several settings. One or two settings go on the closest existing page.
  • Aim for no more than 5 sections on a page. More than that, split the page.
Writing a setting
  • A short name, one line saying what changes and when, and where it applies.
  • Add search words people might use (for example “cost” for budgets).
  • Default values are shown, and a changed value shows a dot and a way to reset it.
  • Dangerous actions go in their own section at the end of the page, with an inline confirmation.
Not in Settings
  • Things done to one object (a member, an AI, a ticket) stay on that object’s own page, with a link from Settings if useful.
  • Personal preferences that people switch often (such as the theme) can also get a shortcut in the account menu.
  • Per-AI options stay on the AI member’s profile; only board-wide limits live in Settings › AI.
