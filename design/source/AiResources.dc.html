AI Team — Resources: what the running AIs use, and what the system does about it

A live view of RAM and CPU for every running AI and for the machine, with Stop and Restart; resource chips on each run; clear notices when the system restarts or stops a run; settings for the memory limit, parallel runs and tool access; and the empty state.
A. Where each piece lives, and why
This board adds resource watching to AI Team. It is based on main: AI Team itself (Now, Flow, You stepped in, Health) is a separate proposal, so the frames below show it only as far as needed to place the new tab. Numbers in the mock-ups are invented but follow the real ones: a CLI uses about 180 MB, five together 0.5 to 0.9 GB, CPU peaks near 2 cores at start and settles at 10 to 45%.
Request
Proposal
Why
1. Watch everything
A fifth tab in AI Team, Resources, after Health. Machine tiles on top, a live chart of the last 5 minutes, then one row per running run with Stop and Restart.
Now says what each AI is doing; Health says whether the feature works. Neither is a place for “is the machine OK”. Same range-free, live layout as Now.
2. On each run
A small RAM and CPU chip on the AI’s card in Now and on the run’s own panel; a Resources strip with a 5-minute chart, peak and restarts inside the run panel and the ticket’s AI activity; two lines on the Timeline hover card.
The ticket card on the board stays quiet: resources are a concern of whoever watches the team, not of everyone reading the board. The chip turns amber and red with the number written beside it, never colour alone.
3. Restarted or stopped by the system
A strip on the run (what, when, how much, what to do), a restart badge or a RAM-stop bar on the Timeline, a toast and a bell entry in the app, a desktop notification and the AI Team tab badge when you are away, and an audit entry.
A restart is information, a stop needs you. So a restart is a quiet amber notice; a stop is a card in Needs you with a Retry button.
4. Settings
A Resources card in the AI settings: memory limit per run, runs at the same time, and a live estimate against this machine. Per AI member: access to the resource tools (None, View, Control) and its own slots.
The estimate (“4 runs at up to 2 GB can use 8 GB; 8.9 GB is free”) turns two abstract numbers into one decision.
5. Nothing running
The machine tiles stay, the chart is flat, the table says “No AI is running” and shows the last run’s peak.
The tab is still useful before anything runs: it tells you how many runs this machine can take.
B. Resources: every running AI, and the machine
The tab answers three questions in order: is the machine OK (tiles and the one-line verdict), who is using what (chart), and what do I do about it (table with Stop and Restart on each row). It updates every 2 seconds and needs no date range.

B2. Reading it, and the two actions
How to read it
  • Tiles. Machine RAM and load are the machine as a whole, not only the AI. “AI processes” is what the AI CLIs add, as a share of the machine.
  • Colour. A bar is green below 65% of the limit, amber from 65%, red from 90%. The percentage is always written. The verdict line goes amber when a run is amber, and red when free RAM is under 10%.
  • CPU. 100% is one core. A run that just started shows near 190% for a few seconds and the chip says starting, so it is not read as a problem.
  • Peak is the highest RAM the run has reached, so a dip after a restart does not hide it.
Stop and Restart
  • Stop ends the run as stopped by you. Partial work in the folder is kept. A confirm popover names the AI, the ticket and what happens.
  • Restart starts the CLI again inside the same run (same run number, restarts +1). Use it when a run is climbing. It is not a new run and does not count as a retry.
  • Both are off for a viewer, with a tooltip that says why. Every use is in the audit log with the name of the person or AI.
  • Rows are sorted by RAM, highest first, and keep their order while you hover so a button never moves under the pointer.

Rules
  • Restart is information: a toast, a bell entry, a dot on the tab, an entry in the audit log. No desktop notification by default, because it needs nothing from you.
  • Stop needs you: a card in Needs you, a count on the AI Team tab, a desktop notification and, if you use it, the daily digest line (“2 runs restarted and 1 stopped for memory”).
  • Both are two new events in Settings › Notifications, each with in-app and desktop switches like the others. Restart: in-app on, desktop off. Stop: both on.
  • Several restarts of one run in a few minutes are one notice with a count, not a stream.
  • The audit log keeps who or what acted: “System” for automatic ones, a person or AI member for Stop and Restart pressed by hand, with the RAM value at that moment.

To confirm before building
  • What Restart means. This board assumes the CLI starts again inside the same run and resumes its session. If a restart is really a new run, the Timeline needs a new bar and the “restarts” count becomes “retries”.
  • Restarts before a stop. Drawn as 2, a fixed rule. If it should be a setting, it goes next to the memory limit.
  • Windows. Per-run RAM cannot be read there today; the board shows the fallback (F2).
  • Who may press Stop and Restart. Assumed to be the same people who can stop a run today.
  • History after a restart of the app. The 5-minute chart restarts empty; peak and restarts survive on the run.
  • Default limit. The server default is 4 GB; this board shows 2 GB as a suggested lower default because a normal CLI is about 200 MB.
Rules for access
  • An AI with Control cannot stop its own run through these tools, so it cannot end the work it is doing by mistake. It can ask for Restart on itself.
  • The PM row is locked because it is the Autopilot delegate: it already decides approvals as a person would, so showing a lower level would be untrue. The lock explains itself and links to Autopilot settings. If the delegate is changed, the new delegate gets the lock and PM goes back to None.
  • People: everyone in the project sees the Resources tab. Stop and Restart need the same rights as stopping a run today; a viewer sees them off.
  • Every Stop and Restart by an AI is in the audit log with the AI’s name and, where it was asked for, the approval that allowed it.
