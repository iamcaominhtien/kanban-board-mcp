Screen — v1 proposal

AI accounts — sign in once, share between AI members

A list of AI accounts (one sign-in of one CLI), a sign-in window with a real terminal that tells you what it is waiting for, choosing an account when creating or editing an AI member, how members show their account and what happens when it is signed out, and the new CLI types: Codex, opencode and Antigravity.
A. Where each piece lives, and why
Desktop only. An AI account is one sign-in of one CLI (Claude Code, Codex, opencode or Antigravity). Several AI members can pick the same account: sign in once, and when it expires fix it in one place. The older ways stay: the login already on this computer, and API keys for providers the board calls itself. Only a person can sign in; an AI has no way to open or use the terminal. Mock terminal text is illustrative: each CLI words its own prompts.

Proposal
Why
1. The list
A third tab on the Members page, AI accounts, next to Humans and AI. A link “Manage AI accounts” in Settings › AI, beside “Manage AI members”.
People and AI members already live on this page, and an account is something an AI member picks. No new sidebar item. An account belongs to this computer, not to a project, so the tab shows all of them and says how many members of this project use each.
2. Add and sign in
A short modal in three steps: choose the CLI, name it, sign in. The sign-in step has a real terminal in the middle, a one-line status above it and the few actions that help below it.
A modal because signing in is one task with a start and an end, and nothing else on the page matters meanwhile. A docked panel would invite people to keep working while a login waits for them in a corner.
3. Choose when creating a member
In the Connect step, a list of accounts for that CLI with “Use the login already on this computer” kept as the last choice and New account… opening the same modal on top.
The old way stays exactly as it was. Nobody has to create an account to keep working.
4. Where a member shows its account, and signed out
A second line under the connection in the AI list, an Account row in the profile, a state card Account needs sign-in, and one banner and one notification per account, not per member.
Three members on one account fail together; they should be told together and fixed once.
5. New types
Codex, opencode and Antigravity in the Type step, under “Runs on your computer”. Each says whether the CLI is found and whether it has an account.
opencode’s free models need no account, so opencode can be chosen without one. Antigravity is listed but its runs do not start yet; it carries a temporary Not ready chip and the Connect step says so.
B1. AI accounts, the list
One row per account: its name, the CLI, what it is signed in with, whether it works, and how many AI members use it. The one that needs attention has its button in the row and a banner above, so it is found in either place. Signed-in accounts offer Check now; the menu holds the rest.

C4. Reading the terminal, and what is not shown
Why this shape
  • One sentence, not a wizard. Each CLI asks different things, in a different order, with options of its own. A fixed wizard would be wrong half the time, so the app never claims a step it cannot see.
  • Amber means you. Whenever the CLI is waiting for a person (choose, paste, press Enter) the bar is amber and says exactly which key or action. Blue means nothing is needed from you.
  • Help where it is awkward. A key row (arrows, Enter, Esc) for people unused to terminal prompts, a Paste code button because pasting into a terminal is unreliable, and Open in browser / Copy link when a link appears. All of them just send what you could type.
  • The terminal always works. Any option a CLI offers (region, workspace, device code) is answered right there. The bar adapts when it recognises a prompt and falls back to “Waiting for the CLI…” when it does not.
  • Safe by construction. Only a signed-in person can open this window; there is no tool an AI member can use to start or type into it. The terminal output is not logged and not stored, and a typed code never leaves the window.
Per CLI, as far as known
  • Claude Code: subscription only (Pro, Max, Team). A Console sign-in without an API key is stored outside the account’s folder, so two such accounts would not stay apart; API billing stays an API-key AI member. Runs claude auth login --claudeai: a browser, sometimes a code to paste. Reports email and plan.
  • Codex: sign in with ChatGPT in the browser, or with a device code shown in the terminal. Reports only “Logged in using ChatGPT”.
  • opencode: free models need no login at all; an account matters only for paid providers (an API key or OAuth). Lists providers, not who.
  • Antigravity: a method menu, the browser, an authorization code to paste, then a folder-trust question (section C2b). Reports only whether a call works.
  • These are what the status line can recognise. A new version that asks something else still works in the terminal.

E3. Signed out, and sharing
When an account is signed out
  • Found when a run fails with a sign-in error, and by a quiet check every few minutes and on opening the page. The account goes to Needs sign-in; every member on it follows.
  • Told once. One banner on the AI list and on the accounts tab, one notification for the account (in the app, and on the desktop if enabled), one card in AI Team › Needs you with Sign in again. Not one per member.
  • The run that was going fails with the reason “Account signed out”, with Retry. Queued runs are held and start by themselves after sign-in, in order.
  • Only a person fixes it. Sign in again opens the same window as adding. An AI member that sees the failure can only comment on it; it has no way to sign in.
  • After sign-in every member on the account is back at once; the banner disappears and a toast says how many runs restarted.
Shared accounts
  • The member picker says how many members already use an account, and warns that they share one limit (plan, rate limit, daily cap).
  • Account rows show members from this project and, in the hover, from other projects: “3 here, 1 in Mobile App”.
  • Removing or signing out an account that is used elsewhere names those members too.
  • Costs: an account on a subscription is not metered; an API-key account shows no dollar amount here, only on the member as today.

To confirm before building
  • Where the login is kept. Each account has its own CLI home folder, so accounts never mix with the login already on the computer. Codex, opencode and Antigravity keep a file in it (mode 0600); Claude Code on macOS keeps a keychain entry named from that folder. A file in the folder can be read by any program running as the person, so the folder should not be synced or backed up to the cloud (the add-account notice says so).
  • Who is signed in. Only Claude Code can say. For the others the account shows the method (and plan when known), and the name the person typed. Taken: options (a) and (b) from the review. Reading the email field of a CLI’s token file (option c) is not assumed, because it would contradict “Kanban never reads the login”. Consequence: a duplicate of the same login cannot be detected for Codex, opencode and Antigravity.
  • Claude Code accounts are subscription only. A Console sign-in without an API key is stored outside the account’s folder, so two accounts would not stay apart. API billing remains an API-key AI member.
  • opencode needs no account for free models. The Type and Connect steps offer “Free models, no account”, with the privacy line, and accounts are only for paid providers.
  • Antigravity. The Not ready chip is temporary: it can become a runner (agy -p with stream-json) in the same effort. The last sign-in question is a folder-trust prompt for the folder the login ran in; a headless run in an untrusted folder works, so it does not block runs. The sign-in therefore starts in the account’s own folder, and the window shows Done instead of closing by itself, because the status check may succeed before that question is answered.
  • The older promise (“Kanban never starts a login”) is reworded: Kanban now starts the CLI’s login in a terminal only a person can use; the token is never read by Kanban.
  • Who may manage accounts is assumed to be the same people who manage AI members.
  • Status check. Where a CLI has no cheap check, a failed run is what marks an account signed out.
  • Moving an existing login. “Move to an account” signs in again in the new account’s folder; it does not copy the old token.
