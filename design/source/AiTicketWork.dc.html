Component — v2

AI work on tickets

A ticket is assigned to an AI team: a lead (Claude Code) and the roles it calls on. The lead does the work and decides how; the board only shows it. Nothing the board draws can hold, gate or approve what the team does: no review gate, no status ceiling, no approval, no hold on a ticket. You can send the team a message at any time (Send to {team}), answer when it asks, stop a run, and read the lead’s Report. Desktop only. Sample project: Kanban Board (KAN).

D
Run lifecycle and the run panel
A run is one Claude Code session of the team’s lead. The diagram shows its states and what you can do in each; the panel is where steps, files, commands, tests and the Report live.
1. State machine — the same eight states; the actions are new
Queued
Sees Run #3 is queued and why it waits, in amber: a free slot, the account, an earlier run of the team on the same ticket.
Can Cancel run.
Starting
Sees Run #3 is starting. The start times out after 180 s and the run fails.
Can Stop run.
Running
Sees Run #3 in progress, the steps as they happen, time, cost and tokens.
Can Stop run, Tell the lead now.
Needs input
Sees Run #3 is waiting for your answer and the question card (E). The run stays here until its roles are done.
Can Answer and resume, Stop run.
Finished
Sees Run #3 finished and the lead’s Report. The ticket is where the team left it; nothing moves by itself.
Can Run again.
Failed
Sees Run #3 did not finish and the reason in red, for example Claude Code exited with code 1.
Can Retry.
Cancelled
Sees Run #3 was stopped and who or what stopped it (Cancelled by An Nguyen, The ticket was reassigned.).
Can Run again.
Timed out
Sees Not produced by the v2 server: there is no run time limit. The chip stays in the table in case a limit is added.
Can Retry.
