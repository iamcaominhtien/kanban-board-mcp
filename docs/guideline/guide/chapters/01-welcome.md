Kanban Board is a board for your own work. It keeps tickets, Docs pages, ideas and AI members in one place, on your computer. Nothing is sent anywhere unless you turn on a feature that talks to an AI provider.

## What you can do with it

- Plan work on a **Board**, **List** or **Timeline**, with tickets that carry criteria, sub-tickets, comments, test cases and git branches.
- Write **Docs** pages next to the work, with versions, links between pages and tickets, diagrams and sketches.
- Capture and sort **ideas** in the Idea Space before they become tickets.
- Add **AI members** that work on tickets for you, and ask the **Board AI** about the board.
- Connect your own agent over **MCP**: it sees {fact:tool_count} tools for tickets, Docs and the AI team.

## Key ideas

| Idea | What it means |
| --- | --- |
| Project | A set of tickets and Docs pages with a short key, for example `KAN`. |
| Ticket | One piece of work. It has a type ({fact:ticket_types}), a priority ({fact:ticket_priorities}) and a status. |
| Status | Where the work is: {fact:ticket_statuses}. |
| Member | A person or an AI that can be assigned tickets and @mentioned. |
| Docs | A page tree per project, stored as Markdown. |
| Idea | A thought that is not yet a ticket. It lives in the Idea Space and can be promoted. |
