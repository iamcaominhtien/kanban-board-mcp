## Acceptance criteria

Criteria are one-line checks that say when a ticket is done. Write each one so a person (or an AI) can check it: a number or a visible behaviour, not “works well”. Each criterion has its own checkbox. A ticket can be set so that **Done requires** every criterion to be ticked.

## Sub-tickets

A sub-ticket is a ticket with a parent. Create one from the parent ticket. Use sub-tickets when each part can be finished and checked on its own. Use the checklist of **sub-tasks** when a step is too small to be a ticket.

!!! tip "AI help"
    **Split with AI** on a parent ticket proposes sub-tickets with blocked-by links. You approve the draft; nothing is created before that ({ch:board-ai}).

## Blocks and links

- **Blocks / blocked by** says that one ticket must finish first. A blocked ticket shows a marker on its card.
- **Link** relates two tickets without an order.
- **Link a Docs page** from a ticket to the page that explains it. The page shows the ticket under “Referenced by” ({ch:references}).

## Estimates and dates

Give a ticket an estimate and start and due dates. Dates put it on the Timeline ({ch:views}). The AI guide in {ch:ai-members} uses the scale 1, 2, 3, 5, 8, 13: from 8 up, think about splitting.
